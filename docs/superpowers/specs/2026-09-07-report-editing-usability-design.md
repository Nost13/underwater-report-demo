# 보고서 편집 사용성 개선 설계

작성일: 2026-09-07
기준 버전: a62c92a
상태: 대화에서 확인된 요구사항 반영, 문서 최종 검토 대기

## 1. 목적과 우선 규칙

기존 보고서 작성 흐름을 유지하면서 2026-09-07의 16개 개선 요청과 후속 확인을 반영한다. 실제 구현 및 배포 완료를 뜻하는 문서가 아니다.

- 빌지킬은 직사각형이다. 기존 타원형 빌지킬도 위치와 크기를 유지하면서 직사각형으로 전환한다.
- 서머리 확인 화면의 Finding Matrix에는 현재 Scope에 존재하는 항목만 표시한다. Hull과 Niche가 모두 있으면 별도 표로 나누며, 없는 종류의 표는 숨긴다.
- 위 화면 표시 변경과 Word 템플릿은 분리한다. Word의 고정 양식과 없는 구역의 빈칸 유지 규칙은 변경하지 않는다.
- 도형 추가 및 이름·연결 구역·모양·크기 수정은 사용자가 확인한 범위다.
- 위치도 확정 전 컨디션 입력 금지는 유지한다. 최종 확인사항 미완료 때문에 Word 다운로드를 막는 정책은 변경한다.
- 기존 작업·사진·순서·컨디션·수동 문구·배치 기록을 보존한다. 서버 공유나 외부 인력 정보 게시를 추가하지 않는다.

## 2. 접근 방법

기존 저장 모델을 확장하고 관련 편집 화면을 작은 단위로 분리하는 방법을 채택한다. 화면만 수정하는 방법은 신규 인원과 사용자 표식의 지속 저장을 해결하지 못한다. 서버 중심 재구축은 계정·개인정보 공유 범위를 넓히므로 이번에는 채택하지 않는다.

네 작업 묶음으로 나눈다: 입력·인력, 위치도, 사진, 서머리·출력. 공통 저장 호환성을 먼저 정리하고 각 기능을 연결한 뒤 통합 검증한다. 무관한 화면과 보고서 양식은 재설계하지 않는다.

## 3. 입력 화면 및 일정 선택 (요청 1~4)

- 일정 후보 버튼과 드롭다운의 중복을 없앤다. 작업 예정일, 단일 일정 후보 목록, 선택 일정의 상세 정보로 구성한다.
- 후보마다 ETA, ETD, 부두를 표시하고 작업 예정일을 포함하는 후보를 안내한다. 일정 변경은 명시적인 적용 동작으로 수행한다.
- ETA/ETD 등 실제 적용값의 기존 자동·수동 계산 규칙과 늦게 도착한 조회 응답 방지 규칙을 유지한다.
- Report Information 입력 글자는 기본 16px 이상, 주요 입력칸과 버튼은 높이 44px 이상을 목표로 한다. 좁은 화면에서는 열을 줄여 가독성을 유지한다.
- 시간 입력, 자동·수동 표시, 자동값 복원 버튼의 자리를 일정하게 배치한다. 입력값의 기준선을 맞추며 빈 보조 영역 때문에 특정 입력칸만 내려가지 않게 한다.
- Scope 생성 후 구역 수와 안내는 왼쪽, 다음 단계와 초기화는 오른쪽에 정렬한다. 좁은 화면에서는 일정한 간격으로 줄바꿈한다.
- 인력 검색 결과가 없으면 검색 이름을 채운 새 인원 등록 창을 제공한다. 한글명/영문명, 역할, 자격명, 자격증 번호를 입력한다. 이름 중 하나는 필수이며 없는 자격정보는 임의 생성하지 않는다.
- 새 인원에는 자격증 번호와 별개인 안정적인 ID를 부여한다. 기존 등록 인원과 번호/이름 중복을 확인하고 자동 덮어쓰지 않는다.
- 기본 인력 목록에 브라우저의 사용자 등록 DB를 합쳐 검색한다. 저장 후 즉시 현재 보고서에 추가하고 새 작업에서도 검색할 수 있게 한다.
- 보고서에 선택한 인원은 그 작업의 스냅샷으로 보존한다. 인력 DB 수정이 과거 보고서를 소급 변경하지 않는다. 추가 인력은 브라우저 로컬 보관임을 표시하고 백업/복원 및 충돌 처리에 포함한다.

## 4. 위치도 편집 (요청 5~7 및 후속 확인)

- 도면 가로/세로 위치와 크기에 슬라이더와 숫자 입력을 함께 제공한다. 표시 단위는 %로 통일하고 입력값과 슬라이더를 동기화한다.
- 빈 입력·입력 중 소수·유효 범위 밖 숫자를 처리하고 유효하지 않은 값이 저장되지 않게 한다. 비율 유지 상태에서는 숫자 입력에도 같은 비율 규칙을 적용한다.
- 표식 관리 목록에서 현재 Scope 구역, 연결된 표식, 연결 누락을 확인한다. 기존 표식 편집 또는 새 표식 추가를 제공한다.
- 표식은 안정적인 ID, 표시 이름, 모양, 좌표·크기, 연결된 구역 ID들을 갖는다. 기존 그룹 기반 기본 배치는 호환 변환하여 유지한다.
- 추가/수정 창에서 이름, 연결 구역, 모양, 위치와 크기를 변경한다. 이름 변경은 보고서의 실제 Scope 명칭을 자동으로 바꾸지 않는다.
- 여러 구역을 같은 표식에 연결할 수 있고 앞/뒤 등 한 구역의 복수 표식도 유지한다. Word는 해당 상세 구역에 연결된 표식만 합성한다.
- 빌지킬 기본 모양과 기존 빌지킬의 변환 결과는 RECTANGLE이다. 수량별 분할, 사이드/바텀 분리, 기존 좌표와 크기는 유지한다. 나머지 Niche는 기본 원형이며 명시적으로 모양을 바꾸기 전에는 원형을 유지한다.
- 표식 삭제나 연결 변경 시 영향을 받는 구역을 보여준다. 필수 연결 누락이 있으면 위치도 재확정을 요구하며 컨디션 입력을 임의 해제하지 않는다.
- Scope가 바뀌어도 유지되는 구역의 사용자 표식과 편집값은 보존한다. 사라진 연결은 무관한 새 구역에 자동 연결하지 않는다.
- 이미지 교체로 표식을 초기화하지 않는다. 이름표와 연결선은 편집 보조로만 사용한다.
- 사용자 표식과 연결은 자동 저장, 작업 백업, IMO 배치 보관에 포함한다. 평균 배치 계산에서는 이름이 아닌 호환되는 부위·모양·뷰·수량을 기준으로 삼고 사용자 임의 표식을 다른 부위의 평균에 섞지 않는다.
- 편집 화면, 예상 출력, Word에서 같은 연결과 형상을 사용한다. Word의 고정 이미지 표 크기는 유지한다.

## 5. 사진 작업 (요청 8~12)

- 폴더 생성 성공 후 생성된 루트 이름과 폴더 구조를 보여주고 다시 열어볼 수 있는 버튼을 제공한다.
- 기본 범위는 선택한 폴더의 웹 내 목록 보기 및 해당 폴더를 시작 위치로 하는 재선택이다. OS 탐색기 직접 실행 지원 여부는 구현 시 공식 API와 실제 브라우저로 확인한다. 지원하지 않으면 탐색기 열기라고 잘못 표시하거나 로컬 경로를 추측하지 않는다. 외부 실행 프로그램 설치는 범위 밖이다.
- 선택 취소나 폴더 권한 거부 시 기존 작업과 생성 결과를 보존한다.
- 사용자 화면에서 샘플 사진 생성·배정 및 관련 안내를 제거한다. 기존에 사용자가 보관한 사진은 삭제하지 않는다. 테스트는 별도 합성 사진 입력으로 변경한다.
- Report Input 미배정 사진 패널에 1/2/3/4열 선택과 폭 조절을 제공한다. 최소 썸네일 폭과 본문 작업 공간을 확보하며 좁은 화면에서는 별도 확장 패널로 전환한다. 선택한 표시 설정은 보존한다.
- 사진의 최근 두 단계 폴더 경로와 파일명을 유지한다. 배정 대상 구역·단계를 패널에 명확히 표시한다.
- 배정 대상 버튼의 글자 대비를 강화한다. 현재 선택 상태는 진한 색·체크·문구를 함께 사용하며 단순히 흐리게 표시하지 않는다.
- 사진 드래그 시 대상 사진의 앞 또는 뒤에 삽입선을 표시한다. 마우스 위치로 앞/뒤를 결정하고 첫 위치·마지막 위치·다음 행 경계에서도 실제 결과가 삽입선과 일치해야 한다.
- 기존 선택 순서, Ctrl/Shift 선택, 키보드 순서 변경, 개별 캡션과 Report Use 설정을 보존한다.

## 6. 서머리와 결과 문구 (요청 13~15 및 후속 확인)

- 결과 문구 창은 제목과 본문을 세로로 배치한다. 제목은 전체 폭의 자동 높이 여러 줄 입력을 사용해 긴 제목을 숨기지 않는다.
- 저장·취소·자동 문구 복원의 우선순위를 구분하고 아이콘과 텍스트를 정렬한다. 버튼 최소 높이, 키보드 포커스, 접근 가능한 이름을 갖춘다.
- 서머리 웹 화면에는 Scope에 존재하는 Hull/Niche 행만 표시한다. 값이 없는 현재 Scope 행은 빈 값과 미입력 표시로 남기되, Scope에 없는 행을 생성하지 않는다. Rating 0은 값이 있는 행으로 취급한다.
- Hull과 Niche를 각각의 표로 표시하고 기존 구역/Side/12개 Niche 순서를 유지한다. Fin Blade는 디테일에만 포함한다.
- 서머리에서 행별 최종 수정 창을 연다. 집계 행에 연결된 원본 상세 구역과 최종 단계(AFTER 또는 CURRENT)를 보여주고 사용자가 수정할 원본을 선택한다. 여러 구역에 묵시적으로 일괄 적용하지 않는다.
- 수정한 컨디션은 디테일 원본에 반영하고 서머리를 다시 계산하여 웹과 Word 값을 일치시킨다. Coverage에 따른 Rating/Type 자동 계산을 그대로 사용한다.
- 원본 수정으로 기존 컨디션 확인 상태를 적절히 해제하며 기존 확인 절차를 제공한다. 위치도가 미확정이면 서머리에서도 컨디션 수정은 허용하지 않는다.
- 결과 문구의 직접 수정과 자동 문구 복원은 별도로 유지한다. 원본 컨디션이 바뀌면 수동 문구를 덮어쓰지 않고 재검토를 안내한다.
- Word 고정 매트릭스의 빈 구역 유지 규칙과 웹의 행 필터 규칙을 별도의 표현 계층으로 둔다.

## 7. 미완료 상태 다운로드 (요청 16)

- 입력 누락, 미확인 컨디션, 사진 부족, 인원 수 차이 등의 목록은 계속 보여주되 다운로드 버튼을 영구 비활성화하지 않는다.
- 미완료 항목이 있으면 그 내용을 보여주고 사용자가 `미완료 상태로 다운로드`를 선택한 경우 현재 입력으로 생성한다. 완료 표시나 확인 상태를 자동으로 바꾸지 않는다.
- 위치도 미확정 상태에서도 출력 단계 자체는 접근 가능하게 한다. 컨디션 입력 차단과 출력 경고는 서로 분리한다.
- 미확정 위치도는 확인 창에서 합성 제외를 명시하고 해당 그림은 빈 양식으로 남긴다. 미확정 표식을 확정된 것으로 출력하지 않는다. 없는 사진과 관찰값도 임의 생성하지 않는다.
- 템플릿을 읽을 수 없음, 손상 데이터, 실제 파일 생성 오류와 같은 기술적 실패는 정상 다운로드로 취급하지 않고 원인과 재시도 방법을 안내한다.
- 생성 중 중복 실행은 차단한다. 기존 잡번호_선박명 파일명과 문서 순서는 유지한다. 사용자 요청 없는 워터마크나 초안 접미사는 추가하지 않는다.

## 8. 저장 호환성과 실패 처리

- 기존 작업 파일은 신규 필드가 없어도 기본값으로 읽힌다. 과거 빌지킬 형상 변환은 다른 표식의 좌표·모양을 건드리지 않는다.
- 인력 DB와 사용자 표식의 신규 ID 및 연결 구조를 검증한다. 중복 ID, 없는 구역 연결, 범위 밖 숫자, 지원하지 않는 형상을 안내하고 안전하게 복원한다.
- 자동 저장 실패·다른 탭 충돌·가져오기 실패 때 현재 편집값을 잃지 않도록 기존 복구 절차를 유지한다.
- 고객 이름·사진·자격정보가 테스트 파일이나 공개 저장소에 추가되지 않게 합성 데이터를 사용한다.

## 9. 검증 기준

- 일정 선택 UI가 하나만 있고 적용·재선택·수동값 보호가 정상이다.
- 1024px/1440px 화면에서 입력칸과 안내 버튼이 겹치지 않으며 긴 제목 전체가 보인다.
- 신규 인원이 현재 보고서와 새 작업에서 검색되고, 재시작·백업/복원·중복 처리 후에도 유지된다.
- 도면 숫자 입력, 비율 유지, 표식 추가·이름/연결 변경·삭제·복원·Scope 변경이 기존 배치를 보존한다.
- 기존 타원 빌지킬이 같은 크기·좌표의 직사각형으로 바뀌고 웹 예상도와 Word에서도 일치한다.
- 사진 패널 1~4열과 폭 변경, 배정 대상 강조, 앞/뒤/끝 드래그 순서가 실제 브라우저에서 검증된다.
- Hull 단독/Niche 단독/둘 다/빈 Scope/Rating 0의 서머리 행과 표 표시를 검증한다. Word 빈칸 규칙을 회귀 테스트한다.
- 서머리 수정이 선택한 원본과 Word에 동일 반영되고 무관한 구역을 바꾸지 않는다.
- 미완료 내보내기의 취소/확인과 미확정 위치도 제외가 동작하며 컨디션 편집 제한은 유지된다.
- 단위·통합 테스트, 타입 검사, 화면 검사, 실제 합성 DOCX 검사와 배포용 빌드를 수행한다. Word 전체 페이지 렌더링의 미완료가 남으면 통과라고 주장하지 않고 별도 보고한다.

## 10. 설계 자체 검토

- 16개 요청과 후속 변경을 모두 포함했다.
- 웹의 존재 항목만 표시와 Word의 고정 빈칸 유지가 충돌하지 않도록 분리했다.
- 직사각형 빌지킬 규칙이 기존 타원 기본값보다 우선한다.
- 컨디션 입력 제한과 미완료 Word 다운로드 허용을 분리했다.
- 로컬 인력 DB를 서버 공용 DB로 오해하지 않도록 저장 범위를 명시했다.
- 구현 및 배포 전 단계이며, 현재 공개 사이트를 변경하지 않았다.
