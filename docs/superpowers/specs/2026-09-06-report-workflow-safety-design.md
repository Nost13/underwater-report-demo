# 보고서 작성 흐름·저장·재사용 개선 설계

작성일: 2026-09-06

상태: 선종·크기별 평균 배치 추천까지 반영한 최종 설계안. 구현 전 사용자 검토본.

## 1. 목적과 승인된 범위

긴 보고서 작성 중 데이터 유실을 방지하고, 기존 작업을 유지한 채 Scope를 수정하며, 자동 입력값과 실제 확인값을 구분한다. 사진 배정과 최종 점검을 편하게 하고, 보고서용 자동 결과 문구를 직접 수정할 수 있게 한다.

사용자의 최신 지시가 앞선 제안보다 우선한다.

- **선박 위치도 확정 전에는 컨디션을 입력할 수 없다.** 이 선행 조건을 해제하거나 입력 우회 경로를 추가하지 않는다.
- **선박 이미지를 교체해도 기존 도형의 위치·크기·모양을 유지한다.** 새 파일 업로드를 자동 배치 초기화로 취급하지 않는다.
- IMO별 선박 이미지와 배치를 저장하고 다음 작업에서 사용자가 명시적으로 불러올 수 있게 한다.
- 사이드뷰·바텀뷰의 도면을 고정된 도형 배치에 맞춰 조정하고, 같은 선종·비슷한 크기 선박의 확정 배치가 쌓이면 도형별 평균 위치·크기를 추천한다.
- 추천 우선순위는 같은 IMO의 확정 배치 → 같은 선종·유사 크기의 평균 배치 → 선종 기본 배치 → 공통 기본 배치다. 평균값은 추천이며 위치도 확정을 대체하지 않는다.
- 서머리 웹 매트릭스 확대, 전체 빈칸 표시, 원본 디테일 연결 등 별도 서머리 화면 개선은 제외한다.
- 서머리에는 작업 종류와 레이팅을 반영한 자동 결과 제목·본문을 보여주고 이를 수정하는 창만 추가한다.
- 문서 목차, 매트릭스 기준 섹션 순서, 12개 니치 순서, Fin Blade의 서머리 제외는 변경하지 않는다.
- 기존 원형 유지, 편집 전용 연결선·이름표, 고정 Word 이미지 표, 사진 캡션, 파일명 규칙은 보존한다.

## 2. 구현 단위와 순서

서로 검증할 수 있는 다섯 단위로 나눠 진행한다.

1. **저장과 선박 배치 재사용:** 로컬 자동 저장, 복원, 사진 포함 작업 파일, 사이드뷰·바텀뷰 도면 맞추기, 이미지 교체 시 배치 유지, IMO별 저장·불러오기, 선종·크기별 평균 추천.
2. **안전한 Scope 수정:** 유지·추가·삭제 비교, 기존 입력 보존, 삭제된 부위 사진 미배정 전환, 취소·복구.
3. **입력값 신뢰성과 결과 문구:** 시간 자동/수동 관리, 선박 수동 입력, 일정 선택, 인원 검증, 컨디션 확인 상태, 결과 문구 편집.
4. **사진과 디테일 입력 편의:** 폴더 흐름 정리, 일괄 배정, 공통 사진 선택, 그룹 변경 미적용 경고, 구역 진행 상태.
5. **최종 점검:** 전체 구성 점검, 필수 수정/확인 권장 구분, 전체 문서 순서 확인과 파일명 표시.

이 문서는 제품 동작과 데이터 보호 규칙을 정의한다. 세부 구현 계획은 이 설계의 확인 이후 각 단위별로 작성한다.

## 3. 자동 저장·복원·작업 파일

### 저장 방식

- 기존 로컬 전용 특성을 유지한다. 보고서·사진·자격자료를 신규 서버나 외부 서비스에 전송하지 않는다.
- IndexedDB에 버전이 있는 작업 스냅샷과 사진 Blob을 저장한다. 브라우저 저장소는 영구 백업을 보장하지 않음을 안내한다.
- 저장 대상: 선박/잡 정보, 선택한 일정, Scope 초안과 확정 구성, 컨디션과 확인 상태, 사진 원본·배정·순서·캡션·사용 여부, 보고서 라벨, 운영정보와 인원/자격자료, 안전사진, 커버 이미지와 편집값, 위치도와 도형, 결과 문구 수정값, 현재 단계.
- File의 이름·MIME·수정시각과 Blob을 보존한다. 임시 object URL과 디렉터리 접근 권한을 저장 데이터로 재사용하지 않는다.
- 복원 시 File과 미리보기 URL을 다시 만들고, 폴더에 쓰는 작업은 해당 폴더를 다시 선택하도록 안내한다.
- 변경을 묶어 비동기로 저장하고 완료된 트랜잭션에만 마지막 저장 시각을 표시한다. 저장 실패·용량 부족·비공개 모드 제한을 성공으로 표시하지 않는다.
- 자동 복원 확인이 끝나기 전에 빈 초기 상태가 기존 스냅샷을 덮어쓰지 않게 한다. 탭 간 동일 작업 수정은 버전 충돌을 감지하고 덮어쓰기 전에 알린다.
- 마지막 정상 저장본을 보존하고, 복원/새 작업 시작을 명시적으로 선택하게 한다. 새 작업은 기존 작업과 별도 ID를 사용한다.

### 수동 백업

- 기존 JSZip을 활용해 JSON manifest와 사진 원본을 묶은 `.uws-report.zip` 작업 파일을 제공한다.
- 가져오기는 형식 버전, 필수 구조, 파일 참조, 예상 압축 해제 용량을 검사한다. 지원하지 않거나 손상된 파일은 현재 작업을 변경하지 않고 거절한다.
- 사진 포함 여부와 저장 성공 여부를 명확히 표시한다. 복원 실패 시 현재 작업을 먼저 지우지 않는다.

## 4. 사이드뷰·바텀뷰와 선박 배치 추천

### 4.1. 작성 순서와 뷰 구분

- 순서: 선박 정보 입력 → Scope 구성 → 추천 배치 확인 → 도면 불러오기 → Hull 기준에 도면 크기·위치 맞추기 → Niche 미세 조정 → 위치도 확정 → 컨디션 입력.
- 사이드뷰와 바텀뷰는 각각 이미지, 이미지 조정값, 선체 기준, 도형 목록, 확인 상태를 가진다. 두 뷰의 좌표나 평균을 섞지 않는다.
- 사이드뷰는 기본 뷰다. 바텀뷰는 해당 작업에서 사용할 때 추가한다. BOTTOM 구역은 바텀뷰 사용 시 바텀뷰에 연결하고, 바텀뷰를 사용하지 않는 기존 작업은 기존 사이드뷰 연결을 유지하되 화면에 사용 뷰를 명시한다.
- Niche는 기본 사이드뷰를 사용하고 사용자가 바텀뷰에 연결할 수 있다. 뷰를 바꾸면 해당 뷰에 맞는 도형 확인을 요구한다. 이미지를 임의로 반전하거나 다른 뷰의 도형을 자동 복사하지 않는다.
- 현재 Scope가 사용하는 모든 뷰를 확정해야 컨디션 입력과 최종 출력이 가능하다. 사용하지 않는 바텀뷰를 일괄 필수로 만들지 않는다.

### 4.2. 도형을 유지하고 도면을 맞추기

- Hull 단계에서는 기준 도형 배치를 유지하면서 배경 도면의 위치와 크기를 조절한다. 가로·세로 비율 잠금이 기본이며, 필요하면 잠금을 풀어 가로 길이와 높이/폭을 각각 맞출 수 있다. 이미지 조정으로 도형을 이동하거나 원형을 타원으로 변형하지 않는다.
- 그림 자체의 흰 여백이 아니라 선미·선수·선체 상하단 또는 좌우 폭을 기준으로 맞춘다. 이미지 안의 선체 기준과 편집 화면의 도형 기준을 분리해 저장한다.
- Niche 단계에서는 잘 맞지 않는 도형만 개별 또는 다중 선택으로 미세 조정한다. 선박마다 구성품의 상대 위치가 다를 수 있으므로 크기를 맞췄다는 이유만으로 전체 일치를 보장하지 않는다.
- `이미지 교체`: 해당 뷰의 이미지 파일만 교체한다. 고정 편집 좌표의 Hull 기준과 Hull/Niche 도형 좌표·크기·모양은 유지한다. 기존 이미지 배치 영역에 새 이미지를 넣고 사용자가 도면을 다시 맞춘다. 이미지 디코딩 실패나 파일 선택 취소는 기존 상태를 변경하지 않는다.
- 이미지가 달라졌으므로 위치도는 미확정으로 전환하고 Hull → Niche 확인을 다시 진행한다. 기존 컨디션은 삭제하지 않지만 재확정 전 편집과 최종 출력은 허용하지 않는다.
- 같은 IMO의 도면·배치 재사용은 저장 이미지, 조정값, 기준, 도형을 함께 미리보기로 보여준다. `이 배치 사용`을 눌러야 현재 작업에 적용한다.
- 유사 선박 평균 추천은 다른 선박의 이미지를 가져오지 않고 기준 도형 배치만 제시한다. 이미 올린 현재 도면은 보존한다. 추천을 적용하면 도형 배치가 바뀐다는 점을 명시하고 적용 전후 비교와 취소를 제공한다.
- 기본 배치 생성은 초기 작성 또는 사용자가 요청한 초기화 때만 수행한다. 일반 파일 교체와 배치 초기화는 별개다.
- Word에는 선택한 뷰의 이미지 조정값과 확정 도형을 같은 좌표 변환으로 합성한다. 편집용 여백·연결선·선택 핸들은 출력하지 않고 기존 고정 표 크기를 유지한다. 기존 사이드뷰 전용 저장본은 사이드뷰 하나로 복원한다.

### 4.3. IMO별 이력과 대표값

- 유효한 IMO에 선박명, 정규화한 선종, LOA(m), 선폭(m), 저장 시각, 출처 잡번호, 뷰별 이미지·조정값·선체 기준·도형 배치를 연결한다.
- 작업별 확정 이력은 보존하며 최근 또는 이전 작업을 선택할 수 있게 한다. 작업 이력과 평균 계산용 대표값은 구분한다.
- 평균용 대표값은 IMO·뷰·부위·Side·Unit/수량 구성·도형 종류의 의미 키마다 최신 확정값 하나만 사용한다. 같은 선박의 반복 저장으로 가중치가 늘지 않는다. 현재 작업에 없는 부위의 기존 확정 기록은 삭제하지 않으며 기록 시각을 표시한다.
- 미확정 자동 저장본은 평균에 반영하지 않는다. 표본으로 계산한 예측 도형 자체를 새 표본으로 추가하지 않으며, 별도 선박에서 사용자 확정을 거친 뒤에만 대표값 후보로 반영한다.
- 사용자는 대표값의 평균 반영을 제외하거나 이전 확정 기록으로 되돌릴 수 있다. 새 기록이 이상값 검토 중이면 기존 평균용 대표값을 유지한다.
- 선박 선택 시 저장본/추천을 자동으로 찾아 보여주되 작성 중인 배치를 덮어쓰지 않는다. IMO가 없으면 현재 작업 저장은 가능하지만 선박별 대표값 등록과 평균 표본 참여는 제한한다.
- 다음 작업의 Scope 수량이 다르면 동일 의미의 도형 ID는 유지하고 부족한 도형만 추가한다. 예전 작업의 컨디션·사진 배정·작업 완료 상태는 선박 배치와 함께 복사하지 않는다.
- 불러오기 전에 현재 작업을 저장하고, 취소하면 아무것도 바꾸지 않는다.

### 4.4. 평균값을 제시하는 기준

1. **같은 IMO의 확정 배치:** 해당 선박의 기록을 우선 제시한다. 현재 제원과 저장 제원이 다르면 그 차이를 표시한다. 부족한 부위만 다음 단계의 추천으로 채운다.
2. **같은 선종·비슷한 크기의 확정 표본:** 뷰와 부위 의미가 맞는 서로 다른 IMO의 대표값으로 평균을 계산한다.
3. **선종 기본 배치:** 사용자가 별도로 `선종 기본값으로 저장`한 배치다. 개별 선박 확정으로 공통 기본값을 자동 변경하지 않는다.
4. **공통 기본 배치:** 위 자료가 없는 부위의 초기값이다. 저장 자료가 없는 사실을 표시한다.

- 평균 계산의 초기 유사 크기 기준은 대상 LOA와 선폭 각각 ±20%다. 이는 검증된 선박 분류 규칙이 아니라 첫 구현의 추천 필터이며, 추천 근거에 범위를 표시한다. 범위를 자동 확대해 서로 다른 크기군을 섞지 않는다.
- 선종은 명시적 분류/별칭표로 정규화한다. 불명확한 선종이나 단위가 잘못된 제원은 추측해서 분류하지 않는다. LOA/선폭이 누락되거나 0 이하이면 유사 크기 평균을 적용하지 않고 선종 기본값 또는 공통 기본값을 제시한다.
- 사이드뷰는 선미→선수 길이와 선체 상하 범위, 바텀뷰는 선미→선수 길이와 좌우 폭을 각각 0~1로 정규화한다. 도형 중심과 크기를 이 선체 기준으로 저장한다. 흰 여백을 포함한 전체 이미지 픽셀 기준 평균은 사용하지 않는다.
- 대응되는 표본의 중심 좌표와 크기에 동일 가중치의 산술평균을 적용한다. 원형은 중심과 선체 길이 대비 지름 하나를 평균하고 출력 시 원형을 유지한다. 사각형·타원·빌지킬은 같은 형상끼리만 계산한다.
- 부위·Side·Unit·앞뒤 역할이 다른 도형을 섞지 않는다. 다중 도형의 수량 구성이 다르면 대응되지 않는 Unit을 억지로 평균하지 않는다. Hull과 빌지킬의 분할 수는 현재 Scope를 따른다. 수량이 다른 빌지킬은 동일 의미의 전체 구간 기준이 있을 때만 재분할하고, 없으면 기본 배치와 확인 안내를 사용한다.
- 유효 표본이 서로 다른 선박 3척 이상이면 `평균 배치`로 표시한다. 1~2척이면 계산 결과를 `참고 배치 · 표본 부족`으로 표시한다. 부위마다 표본 수가 다르므로 전체 배치에 하나의 척수만 붙이지 않는다.
- 이상값 처리는 표본 5척 이상에서 중심/크기 각 성분의 중앙값과 MAD를 이용한다. 편차가 `max(3 × 1.4826 × MAD, 0.05)`를 넘으면 해당 표본 도형을 평균에서 보류하고 검토 목록에 표시한다. 0.05는 해당 정규화 기준의 5%이며, 모두 같던 기록에 다른 값이 들어오는 경우 MAD=0도 처리한다.
- 이상값 원본은 삭제하지 않는다. 사용자가 실제 배치라고 확인하면 그 대표값을 평균에 포함하거나 해당 선박 전용으로 유지할 수 있다. 사용자가 포함을 확정한 버전은 같은 자동 검토로 반복 차단하지 않는다. 표본 5척 미만은 통계적 이상값 판정을 하지 않고 표본 부족을 표시한다.
- 모든 표본에 정상 좌표·양수 크기·일치하는 뷰/형상 검사를 먼저 적용한다. 도형 평균이 실제 선박에 맞는다는 확률이나 정확도 점수를 임의로 만들지 않는다.

### 4.5. 추천 표시와 누적 데이터 보호

- 추천 영역에는 적용 출처(IMO 기록/유사 선박 평균/선종 기본/공통 기본), 선종, 크기 범위, 뷰, 부위별 표본 척수, 마지막 갱신 시각을 표시한다.
- 예: `Sea Chest · Side view · 컨테이너선 · 유사 선박 8척 평균`. 기록이 부족하거나 일부 부위가 기본값이면 그 부분을 구별한다. 과거 확정값이 많아져도 정확한 배치를 보장한다고 표현하지 않는다.
- 추천 → 도면 맞추기 → 필요한 도형 조정 → 확정 → 대표값 갱신의 흐름을 사용한다. 재조회나 새로운 평균 계산으로 현재 편집 중인 도형을 움직이지 않는다.
- 위치도 기록과 평균 자료도 우선 현재 브라우저에만 누적된다. 여러 PC나 사용자의 자료가 자동 합쳐진다고 안내하지 않는다.
- 배치 기록은 작업 백업과 별도로 내보내기/불러오기를 지원한다. 가져오기 전에 병합 대상을 보여주고, 같은 IMO의 동일 기록 중복은 배제하며 기존 대표값 교체는 확인한다. 추천 평균은 원본 대표값에서 재계산한다.

## 5. Scope 안전 수정

- 최초 생성 후 `Scope 만들기`는 `Scope 수정`으로 전환한다. 기존 구성을 검토할 수 있게 하고 반복 생성으로 작성 내용을 지우지 않는다.
- 변경 전후에 유지/추가/삭제될 섹션과 영향을 받는 사진 수를 보여준다.
- 부위·Side·Unit·Service를 포함한 의미 키로 기존 섹션을 대응시킨다. 같은 구역의 작업 종류가 다르면 컨디션을 다른 작업으로 자동 전이하지 않는다.
- 유지 섹션의 컨디션, 확인 상태, 라벨, WORK PERFORMED 문구, 사진 순서·캡션·사용 여부를 보존한다. 삭제 섹션의 사진은 원본·캡션을 유지한 채 미배정으로 돌린다.
- 새 섹션만 기본값으로 시작한다. 기존 도형은 유지하고 필요한 표식이 추가되면 위치도 재확정을 요구한다.
- 변경 취소 및 직전 Scope 변경 되돌리기를 제공한다. 전체 초기화는 별도의 경고·명시적 확인과 복구 가능한 직전 저장본을 사용한다.
- 사용자 작성 서비스 설명을 Scope 재조정 과정에서 덮어쓰지 않는다.

## 6. 시간·선박·인원 입력

- Work Window는 기존 `16 Hours + 1 Hrs` 형식과 여유시간 규칙을 유지한다. Working Time은 `0 Hrs 49 Min` 형식을 유지한다.
- Work Window / Working Time / Position은 자동 또는 직접 입력 모드를 가진다. 직접 수정하면 수동으로 전환하고 이후 원본 필드 변경으로 덮어쓰지 않는다.
- `자동값으로 복원`을 제공한다. 자동 모드에서 날짜가 지워지거나 역전되면 오래된 계산값을 남기지 않고 비우며 원인을 안내한다. 수동값은 보존하되 원본 날짜의 문제를 별도로 표시한다.
- Position 자동값은 기존 Anchorage 예외와 STBD SIDE / PORT SIDE 풀 명칭 규칙을 유지한다.
- 선박 검색 실패/오프라인에서도 `직접 입력으로 시작`을 제공한다. 필수 선박명과 입력한 제원으로 Scope를 만들 수 있게 한다.
- 작업 기준일과 조회 일정 후보의 날짜·부두·제공되는 항차 정보를 함께 보여주고 사용자가 일정을 적용한다. 제공되지 않은 항차·시간을 만들지 않는다.
- 새 조회 응답이 뒤늦게 도착해 다른 선박 또는 직접 수정한 현재 입력을 덮어쓰지 않도록 요청 식별과 적용 확인을 사용한다.
- 인원 선택은 Supervisor / Diver / 기타 역할을 연결하고 선택 인원 기준으로 수량을 제안한다. 직접 수정한 수량은 유지하고 실제 선택 인원·자격자료와 다르면 확인 권장으로 안내한다.

## 7. 컨디션 확인과 자동 결과 문구

- AFTER의 R0 기본 입력 편의는 유지한다. 부위·Phase별로 기본값/미확인과 확인 완료를 구분한다.
- 조건 편집 또는 그룹값 적용으로 값이 바뀌면 해당 구역의 확인 상태를 미확인으로 되돌린다. 그룹 적용은 기존 개별 override 보호 규칙을 유지한다.
- 구역 확인은 위치도 확정 이후에만 가능하다. 그룹 적용 편집창을 나갈 때 미적용 값이 있으면 적용/버리기/머무르기를 선택한다.
- 사진 수와 컨디션 확인 상태를 기준으로 구역 진행 상태를 계산하고, 다음 미완료 구역으로 이동하는 기능을 제공한다. 단계 번호가 앞이라고 완료로 표시하지 않는다.
- 자동 결과 제목·본문은 실제 Scope의 작업 종류와 디테일의 레이팅·커버리지·관찰 조건을 이용한 결정적 템플릿으로 작성한다. 외부 생성형 API는 추가하지 않는다.
- Inspection / Cleaning / Polishing / Repair / Removal과 복합 작업을 구분하되, 입력하지 않은 제거 물질·손상 없음·작업 성공 등을 추정해 단정하지 않는다. 미확인 기본 R0를 검증된 최종 결과로 서술하지 않는다.
- 기존 서머리 위치에서 자동 문구를 보여주고 `결과 문구 수정` 창으로 제목과 본문을 수정한다. 저장/취소/자동 문구로 복원을 제공한다.
- 직접 작성 문구는 컨디션 변경 때 덮어쓰지 않는다. 근거 입력이 바뀌면 재검토 안내와 최신 자동 초안을 제공한다.
- 화면에 확정한 문구와 Word 5.1 OVERALL RESULT 문구를 동일 데이터에서 출력한다.
- Word의 기존 고정 매트릭스·집계 기준·커버리지에 따른 레이팅 자동 계산은 보존한다. 서머리 웹 매트릭스의 구성은 변경하지 않는다.

## 8. 사진·입력 편의

- `기존 사진 불러오기`를 주 동작으로 두고 `빈 표준 폴더 만들기(선택)`를 분리한다. 폴더 생성이 사진 입력의 필수 선행 단계처럼 보이지 않게 한다.
- 썸네일과 끝 두 단계 폴더 표시를 유지한다. Ctrl/Shift 다중 선택 및 체크박스 선택으로 사진 여러 장을 현재 부위·Side·Unit·Phase에 일괄 배정한다.
- 배정 대상의 풀 경로와 선택 사진 수를 표시하고 명시적으로 배정한다. 기존 사진 순서 뒤에 선택 순서대로 추가한다.
- 미배정과 보고서 제외를 구분한다. 디테일에서 사진 제거 시 미배정으로 복귀하고 원본은 유지한다.
- 가져온 사진을 공통 보관함에서 골라 디테일, 커버, Toolbox, 현장 준비에 사용할 수 있게 한다. 같은 원본의 용도별 참조를 분리해 커버에서 사용했다고 디테일 배정이 사라지지 않게 한다.
- Toolbox와 현장 준비는 각각 2장 슬롯 및 충족 상태를 유지한다. 위치도에는 허용된 이미지 형식만 선택할 수 있다.

## 9. 전체 점검과 출력

- 위치도 미확정은 계속 최종 출력 불가다. 구역 사진 누락·컨디션 미입력/미확인·날짜 역전·필수 커버 정보 누락은 최종 보고서의 필수 수정으로 분류한다.
- 미배정 여분 사진, 의도적으로 보고서에서 제외한 사진, Before/After 사진 수 차이, 인원 수 불일치, 선택적 운영정보 빈칸은 확인 권장으로 구분한다. 없는 구역의 매트릭스 빈칸은 오류로 취급하지 않는다.
- 안전사진은 2장씩 충족 상태와 누락을 안내한다. 누락 상태의 최종 출력에는 사용자가 해당 항목을 검토하도록 한다.
- 최종 출력 전에 필수 수정과 확인 권장을 구분해 보여주고 원래 입력 위치로 이동할 수 있게 한다. 파일명은 기존 `잡번호_선박명_Underwater service report(Detail).docx` 형식을 유지한다. 별도 초안 출력 모드는 이번 범위에 추가하지 않는다.
- 커버 → 1~4 → 서머리 → 평가기준 → 디테일 → 자격자료의 전체 구성 체크를 제공한다. 서머리 입력 화면 자체를 재설계하지 않는다.
- 미리보기의 실제 잡번호를 표시하고 디테일 페이지 수와 전체 예상 페이지 수를 혼동하지 않게 한다. 웹 미리보기는 Word의 최종 페이지 나눔과 다를 수 있음을 명시한다.
- 전체 예상 구성과 실제 내보내기 데이터가 같은 보고서 모델을 사용하게 한다. Word 생성 후에는 샘플 문서를 렌더링해 표 크기·여백·넘침·전체 순서를 검증한다.

## 10. 합격 기준

- 실제 이미지와 여러 사진·자격자료를 가진 작업을 저장, 탭 종료, 복원했을 때 입력·배정·순서·도형·문구가 유지된다.
- 저장 실패, 손상 파일, 지원하지 않는 버전, 탭 충돌을 발생시켜도 현재 정상 작업이 소실되지 않는다.
- 서로 종횡비가 다른 선박 이미지로 교체해도 도형의 정규화 좌표·크기·모양이 그대로이고 위치도 확인이 해제된다.
- 같은 IMO의 다른 작업에서 저장한 위치도를 불러올 수 있으며, 예전 컨디션이 새 보고서로 복사되지 않는다.
- 선체 기준이 같은 도면에 서로 다른 흰 여백·해상도를 사용해도 저장한 상대 위치와 도형 크기가 같고, 배경 이미지를 이동·확대해도 도형 배치와 원형 모양은 변하지 않는다.
- 사이드뷰·바텀뷰의 확정·복원·Word 합성을 각각 확인하고, 사용하지 않는 뷰가 입력을 막지 않으며 사용하는 뷰의 미확정은 입력을 막는다.
- 같은 IMO → 유사 선박 평균 → 선종 기본 → 공통 기본의 우선순위와 부위별 부분 fallback을 테스트한다.
- 서로 다른 IMO 3척의 알려진 좌표로 산술평균을 검증하고 같은 IMO 반복 저장으로 표본 수가 늘지 않는지 확인한다. 1~2척은 참고 배치, 0척은 기본 배치로 표시된다.
- 선종 불일치, ±20% 범위 경계, LOA/선폭 누락, 다른 뷰·형상·Unit 수량이 잘못 섞이지 않는지 테스트한다.
- 미확정값과 예측값 자체가 표본에 들어가지 않고, 이상값 보류/사용자 포함/이전 대표값 유지 및 배치 기록 백업 병합이 의도대로 동작한다.
- 위치도 미확정 상태에서 직접 단계 이동·복원·미완료 항목 이동을 시도해도 컨디션 편집과 최종 출력이 열리지 않는다.
- Scope에 부위를 추가/삭제한 뒤 기존 부위의 내용이 유지되고 삭제된 부위 사진은 미배정에 나타난다.
- ETD/End 삭제·역전 때 자동 계산값이 남지 않고, 수동 입력값은 원본 변경에도 유지된다.
- 검색 실패 후 수동 입력으로 보고서를 시작할 수 있으며 오래된 조회 응답은 현재 선박 정보를 바꾸지 않는다.
- 미확인 기본 R0와 확인 완료 R0가 구분되고, 여러 작업 종류·레이팅 조합의 자동 문구가 입력 근거와 일치한다.
- 결과 문구의 수정/취소/복원, 사진 일괄 배정, 그룹 변경 경고, 구역 진행 상태를 실제 브라우저에서 확인한다.
- 전체 기존 테스트와 추가 테스트가 통과하고, 대표 복합 작업 보고서의 Word 렌더링에서 기존 양식·순서·12개 니치 규칙이 유지된다.

## 11. 범위 밖

- 위치도 확정 전 컨디션 입력 허용.
- 서머리 웹 매트릭스 확대·출처 링크·빈 행 추가 등 별도 화면 개편.
- 클라우드 저장·계정·원격 공유 시스템.
- 선박 교체 시 이미지 인식으로 도형을 자동 이동시키는 기능.
- 입력하지 않은 관찰 사실이나 작업 성공을 AI가 추정하는 문구.
- 이 설계 검토 단계에서의 운영 배포. 개발 검증과 배포 결과는 구분해 보고한다.
